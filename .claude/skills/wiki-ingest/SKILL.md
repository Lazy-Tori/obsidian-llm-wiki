# wiki-ingest — 소스를 위키에 소화시킨다

```bash
VAULT="${VAULT_PATH:-$HOME/second-brain}"   # 어느 디렉토리에서 부르든 이 볼트가 대상
```

## 절차는 볼트에 있다

이 스킬은 **진입점이지 사본이 아니다.** 요약을 여기 두면 규약이 바뀔 때 낡은 절차를 시킨다.

1. `$VAULT/CLAUDE.md` — 「오퍼레이션 > Ingest」 (소스를 줄 때 / 경험을 말할 때)
2. `$VAULT/docs/wiki-conventions.md` §2 (raw 분류) · §6 (상세 절차) · §6.1 (라우팅)

## inbox — 모든 입력의 1차 착지

**받는 즉시 원본을 `inbox/` 에 떨군다 (판단 0).** 대화로 왔든 파일로 왔든 같다.
소화가 중단돼도 자료가 남고, 잔량이 곧 미처리 백로그다.
분류 질문이 착지를 막지 않는다 — 묻는 건 `raw/` 로 옮길 때다.

**"inbox 비워줘"** = 아래를 파일마다 반복:

1. 읽는다 (`.gitkeep` 제외)
2. `raw/` 채널을 정한다 (§2 — conversations·notes·docs·personal·external). 애매하면 묻는다
3. `YYMMDD-slug` 로 **이동**한다 (버퍼→원본. 불변 규칙은 raw 에 들어간 뒤부터)
4. 통독 → 논의 → 소스 페이지 → **기존 페이지 수정** → index·log 부기
5. 끝나면 inbox 는 비어 있어야 한다. 남겼으면 이유를 보고한다

파일이 여럿이면 먼저 목록을 보여주고, 논의가 필요한 것과 기계적으로 처리할 것을 나눠
사용자가 고르게 한다. inbox 는 gitignore — 분류 전이라 사내 정보가 섞일 수 있다.

## 이 스킬이 강조하는 것

- **원본 먼저.** 어디서 왔든 `raw/` 에 저장하고 시작한다 (raw 는 이동 금지라 분류가
  애매하면 미리 묻는다)
- **5단계가 본체.** 새 소스 페이지만 만들고 끝내면 파일 더미가 된다 —
  영향받는 기존 페이지를 찾아 고치는 것이 ingest 다
- **자격증명 값은 `wiki/` 에 옮기지 않는다.** "여기에 있다"만 적는다
- **마무리 검증**: `cd "$VAULT" && python3 scripts/lint_all.py`
  방금 만진 것에 대한 회귀 게이트다. 특히 `lint-backlinks`(선언한 갱신이 실제 반영됐나) —
  규약 §8이 "ingest 에서 가장 새기 쉬운 지점"이라 명시한다.
  모순·승격 후보까지 읽는 전체 검진은 `wiki-lint` 의 일
- 다른 폴더에서 호출됐으면 **원래 하던 작업으로 복귀**한다
