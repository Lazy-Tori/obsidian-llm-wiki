# wiki-daily — 오늘 한 업무를 일지로 남긴다

```bash
# 어느 디렉토리에서 부르든 이 볼트가 대상.
# 설치할 때 자기 볼트 경로로 고치거나 VAULT_PATH 를 내보낸다
VAULT="${VAULT_PATH:-$HOME/second-brain}"
```

절차 원문: `$VAULT/CLAUDE.md` 「오퍼레이션 > Daily」 · 규약 **§11(일지)** · §10 · §5.

## 핵심 — 일지는 종착지가 아니라 입구다

일지만 쓰고 끝내면 무덤이 된다. 쓰면서 아래를 **같이** 갱신하는 게 본체다.

| 일지 섹션 | 같이 갱신할 곳 |
|---|---|
| 작업 | 관련 `builds/` · `1-experiments/` 페이지 |
| **정해진 것** | 해당 `projects/` 페이지 「현재 상태」·「다음 액션」 **★ 필수** |
| 이슈 | 같은 이슈가 2회째면 question·lesson 후보로 **보고**(생성은 안 함) |
| 일정·해야할일 | (없음. 단 5일 넘게 이월된 항목은 프로젝트 「다음 액션」으로 옮길지 묻는다) |

## 절차

1. **재료를 먼저 모은다** — inbox 세션 파일 → 이 대화에서 이미 아는 것 → `캘린더/` 그날
   섹션(19시 이후 제외, **파일·섹션이 없으면 조용히 건너뛴다 — 추측으로 채우지 않는다**)
   → 세션 파일이 가리키는 레포의 그날 git log
2. **반드시 묻는다** — 재료가 많아도 확인차, 적으면 더더욱. 한 번에 묶어서 짧게:
   ① 오늘 해야할일 ② 뭐부터 시작할지(그 항목을 목록 맨 위로) ③ 막힌 것·신경 쓰이는 것.
   재료로 아는 건 질문에서 빼고 **모르는 것만** — 다 아는 날은
   "이렇게 채웠는데 빠진 것 있나?" 확인 한 번으로 줄인다
3. **이미 있으면 덮어쓰지 않고 주입한다** — 하루에 여러 번 불릴 수 있다. 기존 항목은 두고
   새 내용만 추가, `updated` 갱신
4. **미완료 이월** — 새로 만들 때만. 처음 적힌 날짜를 `(MM-DD~)` 로 붙이고 이미 있으면
   그대로 둔다(밀린 일수가 보여야 한다). **지난 일지는 고치지 않는다**
5. **행선지 갱신** (위 표) — 무엇을 고쳤는지 일지에 링크로 남긴다
6. **아웃바운드 확인** — 프로젝트·산출물 링크가 최소 1개. 없으면 위키 노드가 아니라 일기다
7. **부기·검증** — `index.md` 현황의 일지 수만 갱신(개별 등재 안 함),
   `python3 scripts/lint_all.py`. `log.md` 는 안 적는다(볼트 오퍼레이션 이력이라 성격이 다르다)

## 정리 규칙 둘

- **그룹으로 묶는다** — 해야할일·작업은 맥락별로. 레이블은 `**볼드**`, 그룹 사이 빈 줄
- **이슈 스윕** — 이슈에 산문으로 적힌 할일성 문장은 오늘 일이면 「해야할일」 체크박스로,
  미래 날짜면 루트 `예약.md` 에 `- YYYY-MM-DD 내용` 으로. 원문엔 표식만 남긴다

## 하지 말 것

- **추측으로 채우기** — 안 들은 섹션은 비워두는 게 아니라 **지운다**
- **지난 일지 고치기** — 일지는 날짜 스냅샷이라 낡지 않는다. 사실이 바뀌면 오늘 일지에 적고
  프로젝트 페이지를 갱신한다
- **일지에서 바로 lesson 만들기** — 후보 보고만. 승격은 `wiki-emerge` 의 일
- 「배운 것」 섹션 추가 (규약 §11이 의도적으로 뺐다)
- 사용자가 1인칭으로 말한 판단·감정을 매끄럽게 다듬기

다른 폴더에서 호출됐으면 일지를 마친 뒤 원래 작업으로 복귀한다.
