# wiki-challenge — 내 과거 기록으로 내 현재 판단을 반박한다

```bash
# 어느 디렉토리에서 부르든 이 볼트가 대상.
# 설치할 때 자기 볼트 경로로 고치거나 VAULT_PATH 를 내보낸다
VAULT="${VAULT_PATH:-$HOME/second-brain}"
```

Claude 에게 맨몸으로 물으면 일반론이 온다. 이 스킬은 **내가 실제로 겪어서 적어둔 것**만
근거로 삼는다. 그래서 아프고, 그래서 쓸모가 있다.

**결정 전에** 돌린다. 결정한 뒤에 돌리면 변명 재료가 된다.

## 1. 아이디어를 명제로

검증 가능한 **한 문장 주장**으로 정리해 먼저 보여준다 (확인은 안 받아도 된다 —
반박이 엉뚱한 과녁을 때리는 것만 막으면 된다). 전제가 여럿이면 나눈다.

## 2. 근거를 모은다 — `index.md` 부터

- **위반하는 lesson** · **선례 experiment**(특히 `abandoned`) · **열린 question**
- lesson 의 「반례 / 긴장」이 지금 상황과 닿는지
- **project·source 의 실측 기록** — lesson 층이 얇은 볼트에서는 **여기가 가장 단단하다.**
  프로젝트 「현재 상태」·「열린 긴장」과 문서 스냅샷(`projects/<이름>/wiki/`)까지 내려간다

⚠️ **키워드 히트는 근거가 아니다.** 같은 단어가 다른 뜻인지 본문으로 확인한다.
(실제 사례: "코드리뷰" 6건이 전부 *혼자 남의 코드를 정독한 기록*이었고 팀 프로세스가
아니었다 — 문자열만 봤으면 거짓 반박이 됐다.)

## 3. 강도순으로 제시한다

각 반박에 **근거 `[[링크]]` + 무엇이 걸리는지 + 치명적인가 조건부인가**를 붙인다.

| 강도 | 조건 |
|---|---|
| 강함 | `solid` lesson 위반, 또는 같은 시도가 `abandoned` 된 선례 |
| 중간 | `working` lesson 위반, 또는 유사 선례의 부분 실패 |
| 약함 | `tentative` lesson 위반, `stub` 개념에만 걸림 |
| 실측 | project·source 의 실측 위반 — 대조군·재현 있으면 강함, 단발 관측 중간, 인상 수준 약함 |

⚠️ **lesson 이 없어도 반박은 성립한다.** 볼트 초기엔 그 층이 비어 있다. 침묵으로 빠지기 전에
**lesson 층이 빈 것인지 근거 층까지 빈 것인지** 구분한다 — 실측이 있으면 마지막 행으로 판정하고
그 매핑을 밝힌다.

**일반론을 섞지 않는다.** 하고 싶으면 끝에 「위키 밖 내 의견」으로 분리한다.

## 4. 반박이 없으면 없다고 한다

- **침묵** — 이 영역에 기록이 없다 → 새 도메인. experiment 로 시작할 자리
- **지지** — 오히려 뒷받침한다 → 그 링크를 제시
- **얇음** — 걸리지만 전부 `tentative` → 약한 신호로만

거짓 반박은 다음번에 이 스킬을 안 쓰게 만든다.

## 5. 재반박은 새 데이터다

"그건 이래서 다르다"는 답은 **lesson 의 적용 조건을 좁히는 정보**다. 대화로 흘리지 말고
해당 lesson 의 「적용 조건」·「반례」에 추가할지 제안한다. 저장은 `wiki-ingest` 로 넘긴다.

## 하지 말 것

- 위키에 없는 근거로 반박하기 · 없을 때 만들어내기
- `confidence` 무시하고 전부 같은 무게로 제시하기
- 설득하려 하기 — 재료를 주는 것까지가 일이다. 결정은 사용자가 한다
- 이 스킬에서 페이지를 직접 고치기 (제안만)
