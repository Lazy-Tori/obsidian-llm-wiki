# wiki-emerge — 아직 이름 붙지 않은 것을 찾는다

```bash
# 어느 디렉토리에서 부르든 이 볼트가 대상.
# 설치할 때 자기 볼트 경로로 고치거나 VAULT_PATH 를 내보낸다
VAULT="${VAULT_PATH:-$HOME/second-brain}"
```

승격과 이름 붙이기는 이 볼트의 핵심 동학인데 **아무도 발동시키지 않으면 일어나지 않는다.**
ingest 는 새 소스를 소화하느라 바쁘고, lint 는 형식을 본다.

> **lint 는 깨진 것을, emerge 는 아직 없는 것을 찾는다.**

## 1. 범위 — 기본 최근 30일

```bash
grep "^## \[" log.md | tail -20
git log --since="30 days ago" --name-only --pretty=format:"%ad %s" --date=short -- wiki/
```

프론트매터 `updated` 로도 교차 확인한다(git 에 안 잡히는 변경이 있다).
변화가 적으면 범위를 넓히지 말고 **"재료가 얇다"고 보고**한다.

## 2. 네 갈래로 찾는다

| 갈래 | 찾는 것 |
|---|---|
| 근거 → lesson | 독립 근거 2건 이상이 같은 주장을 지지하는데 lesson 이 없음 (규약 §5) |
| 구조 → concept | 여러 lesson 이 한 구조를 다른 각도로 말하는데 이름이 없음 |
| confidence 승급 | `tentative` 에 근거가 더 붙었나 (반대로 반례가 쌓였으면 하향 후보) |
| stub 졸업 | `maturity: stub` 개념에 실제 접점이 생겼나 |

concept 은 사다리 밖이라 승격 조건이 없다 — 링크의 교차점이 필요하면 그냥 만들어도 된다.
lessons 그룹 안에서, 그리고 **그룹을 가로질러** 본다 — 가로지르는 게 대개 더 깊다.

## 3. 억지 패턴을 만들지 않는다

⚠️ **개수보다 주장의 형태를 먼저 본다** (규약 §5). 둘 다 통과해야 후보다:

- **반증 가능한가** — 무엇이 관측되면 틀린 것이 되는지 말할 수 있는가
- **몰랐다면 다르게 행동했을 것인가**

하나라도 걸리면 근거가 몇 건이든 격언이다. (사례: 「실측이 설계를 이긴다」를 근거 3건·
도메인 독립으로 올렸다가 철회 — 적용 조건·반례를 다 채웠는데 주장 자체가 반증 불가능했다.)
사용자가 "lesson 후보"라고 적어둔 것도 이 필터를 면제받지 않는다.

- 근거 **2건 미만은 후보가 아니다** — 무엇이 하나 더 필요한지 적는다
- 표면 유사성(같은 도구·프로젝트)은 패턴이 아니다. **같은 구조**여야 한다
- 기존 lesson 을 다른 말로 바꾼 것은 신규가 아니라 **그 lesson 의 근거**다

## 4. 후보 제시 형식

1. **이름 후보** — 서술형 주장(lesson) 또는 짧은 명사구(concept). 기존 제목 스타일을 따른다
2. **가리키는 페이지들** — 최소 2개, 각각 무엇이 이 패턴을 보여주는지
3. **왜 아직 이름이 없었나** — 흩어져서 / 최근에야 2회가 돼서 / 다른 이름에 묻혀서
4. **제안 confidence·maturity** — 첫 승격은 대개 `tentative`
5. **반대 재료** — 이 패턴을 약화시키는 관찰

## 5. 자동으로 만들지 않는다

**보고하고 만들지 물어본다.** 여럿이면 하나씩 고르게 한다. 사용자가 고르면 그때:

- 원본을 지우지 않고 **링크로 잇는다** (근거 페이지 → 새 페이지 인바운드도)
- `index.md` 등재 + 현황 숫자 + `log.md` (`## [YYYY-MM-DD] promote | 제목`)
- `python3 scripts/lint_all.py` 로 검증

## 하지 말 것

- 근거 1건으로 후보 만들기 · 확인 없이 페이지 생성
- 표면 유사성을 패턴으로 보고하기
- 후보를 억지로 채우기 — **빈손 보고가 정직할 때가 많다**
